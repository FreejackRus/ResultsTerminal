# ResultsTerminal — инструкции для разработки

## Продукт

Независимый настраиваемый терминал выдачи медицинских **PDF**. Один локальный шлюз учреждения обслуживает несколько Tauri-терминалов. МИС реализует наш HTTPS API; оформление, способы входа и оборудование задаются через админ-панель без пересборки.

DICOM, PACS, USB и бинарники медицинских просмотрщиков не добавлять. Исходный `result-terminal` — отдельный проект, его рабочее дерево не изменять.

## Стек и структура

- Node.js 24 LTS, pnpm 11.25.0, TypeScript strict, pnpm workspace.
- `apps/terminal`: React 19 / Vite 7 / PDF.js 6; `src-tauri` — Tauri 2 / Rust, сканер, печать, мониторинг.
- `apps/gateway`: Fastify 5, SQLite через `node:sqlite`, временные пациентские сессии.
- `apps/admin`: панель учреждения и мониторинг устройств.
- `apps/demo-mis`: только синтетические данные, референс API.
- `packages/contracts`: TypeBox-схемы, типы, темы, правила конфигурации.
- `docs/openapi`: генерируется `pnpm openapi`; не редактировать вручную.
- `deploy`, `examples`, `docs`: служба, примеры и руководство интегратора.

## Команды

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm typecheck
pnpm build
pnpm format:check
pnpm contract:check
pnpm test:browser
pnpm openapi
cargo test --locked --manifest-path apps/terminal/src-tauri/Cargo.toml --lib
cargo test --manifest-path apps/terminal/src-tauri/crates/oms_parser/Cargo.toml --target-dir apps/terminal/src-tauri/target
cargo fmt --manifest-path apps/terminal/src-tauri/Cargo.toml --check
pnpm audit --prod
```

`pnpm dev` — только loopback demo. Production launcher требует HTTPS. Для сборки Windows NSIS использовать `pnpm --filter @rt/terminal tauri build --bundles nsis --ci`, Linux DEB — `--bundles deb` на Debian 12. Windows 10/11, Ubuntu 24.04 и Astra SE 1.8 — отдельные цели приёмки, не синонимы совместимости.

## Критические правила

- Идентификаторы, ОМС, номера заказов и штрихкоды — строки. Ведущие нули сохранять.
- Способы входа определяет пересечение настроек и capabilities МИС. Публичный номер без проверочных данных не даёт доступа.
- Сессию и challenge привязывать к конкретному терминалу. Reset, revoke, смена интеграции, expiry и поздние ответы не могут открыть документы другого пациента.
- Ключ МИС только на шлюзе; токен терминала только в native-части. Не добавлять секреты в renderer, VITE-переменные, export настроек или localStorage.
- PDF не сохранять как архив. Спул-файлы удалять, не принимать произвольные пути/URL от МИС в терминале.
- До физической печати проверить PDF. Отправлять последовательно. После неопределённой отправки не повторять документ, не переключать автоматически механизм печати. Явный отказ до отправки отличать от неопределённого результата.
- Мониторинг не должен выдумывать исправность: неизвестное состояние и устаревшая телеметрия показываются явно. WMI/CUPS не доказывают физическую выдачу бумаги; наличие HID не доказывает правильное чтение штрихкода.
- Логи и диагностика — только разрешённые технические поля, без сырых сканов, ключей, ФИО, телефонов, ОМС и PDF.
- Сохранять TLS-проверку, CSP и ограниченный IPC. Системные политики Windows/Astra не ослаблять.
- Реальные аппаратные действия выполнять только в авторизованном тестовом контексте. Mock, компиляция и unit-тест не заменяют приёмку принтера/сканера на каждой ОС.

## Процесс и скиллы

Прочитай затрагиваемую цепочку вызовов, выбери минимальный рабочий срез и проверяемый критерий. Новые требования не должны менять контракт МИС незаметно: обновляй схемы, OpenAPI, демо и проверки совместимости вместе.

Используй доступные скиллы по задаче:

- Agent Skills: `incremental-implementation`, `test-driven-development`, `debugging-and-error-recovery`, `api-and-interface-design`, `security-and-hardening`, `code-review-and-quality`, `documentation-and-adrs`.
- Ponytail: существующие решения, стандартные средства и маленький корректный diff. Простота не отменяет изоляцию сессий и защиту печати.
- Context7: точная документация установленных версий, особенно Tauri **2**, PDF.js и Fastify. Не отправлять внешним сервисам закрытые данные/ключи.
- taste-skill и frontend-ui-engineering: реальные проверки экранов, крупные touch targets терминала; плотность admin-панели не переносить в пациентский UI.
- ECC при доступности: `verification-loop`, `security-review`, `tdd-workflow`. Не включать глобальные hooks и не копировать настройки чужого проекта ради одного workflow.

Не запускать несколько одинаковых workflow подряд. Не добавлять Redis, очередь задач, облачную платформу, плагины МИС или новую тестовую библиотеку без необходимости текущего требования. Подробности исходных решений, происхождение и фактические проверки — в `docs/` и `THIRD_PARTY_NOTICES.md`.
